# @platform/xml

XML の生成と解析。**外部システムとの連携**に使います。

## これは何のためか

**古い業務システムは XML でやり取りします。**
銀行、公的機関、EDI——**JSON になっていない**ところが多くあります。

## 使う前に知っておくこと

| | |
|---|---|
| **`&` は最後に戻す** | エスケープの順序を間違えると、**`&amp;amp;`** になります |
| **`undefined` の属性は出しません** | 空文字とは違います——**`attr=""` と属性なしは、受け側で意味が変わる**ことがあります |
| **途中が欠ければ `undefined`** | 深い階層を取るとき、**途中で無ければそこで止まります**——例外にはなりません |
| **文字コードに注意** | Shift_JIS を要求する相手がまだあります——**宣言と実際を揃えて**ください |

## よく使うもの

```ts
import { buildXml, parseXml, escapeXml } from "@platform/xml";
import { buildXml, parseXml, selectXml, escapeXml } from "@platform/xml";

const xml = buildXml({
  name: "請求書",
  attrs: { 版: "1.0" },
  children: [
    { name: "取引先", text: "A&B商事" },   // 自動でエスケープされる
    { name: "金額", text: 100000 },
  ],
}, { indent: "  " });

const node = parseXml(xml);
selectXml(node, "金額")?.text;   // "100000"
```

## なぜ要るか

業務では**まだ XML が現役**です——電子申告(e-Tax・eLTAX)、EDI、
銀行の一部 API、SOAP、官公庁の様式。JSON に置き換わっていません。

## エスケープを忘れると壊れる

取引先名に `&` が入るのは普通で(「A&B商事」)、そのまま出すと
**ファイル全体が読めなくなります**。受け取った側は「壊れています」としか言えず、
原因の特定に時間がかかります。

`buildXml` は**すべての値を自動でエスケープ**します。

## 日本語のタグ名に対応

官公庁の様式は日本語のタグを使います(`<請求書>` `<取引先名>`)。
XML の仕様上も有効なので、解析できるようにしてあります。

## 対応しないもの

**軽量パーサ**です。次には対応しません:

- 名前空間の解決(`soap:Body` は**そのままの名前**として扱う)
- DTD・実体宣言(無視する)
- スキーマ検証

**複雑な XML を扱うなら専用ライブラリ**を使ってください。
ここが想定するのは**素直な構造の設定ファイル・API 応答**です。

## 壊れた XML は例外

閉じタグが合わなければ例外を投げます。黙って部分的な結果を返すと、
**足りない項目に気づかないまま処理が進みます**——受け取った申告データが
途中で切れていても分かりません。
