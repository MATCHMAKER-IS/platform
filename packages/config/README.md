# @platform/config

設定の管理（既定値・上書き・型付き取得）。

## これは何のためか

**「どこで設定されているか分からない」を無くす**ためのものです。

環境変数、DB、コードの既定値——**3 か所に散らばる**と、
**なぜこの値になっているのか**が誰にも分からなくなります。

## 使う前に知っておくこと

| | |
|---|---|
| **優先順位を決めておく** | 「DB > 環境変数 > 既定値」のように**一方向**に。**場所によって順序が違う**と追えません |
| **秘密は入れない** | 設定は**画面に出す**ことがあります。鍵は `@platform/env` か Vault へ |
| **既定値は「動く値」に** | 「未設定」で落ちるより、**動いて警告**する方が親切な場面があります——ただし**秘密は例外**です |
| **変えたら記録する** | 「昨日まで動いていた」の原因は、**設定の変更**が多いところです |

## よく使うもの

```ts
import { createConfig, defineSchema } from "@platform/config";
// packages/xxx/tsconfig.json
{ "extends": "../config/tsconfig.base.json" }
```

設定を1か所に集約することで、パッケージ間の設定ゆれ(strict の抜け等)を防ぎます。

## テストが無い理由

このパッケージは **tsconfig と vitest のプリセットだけ**で、ランタイムコードを持たない
(`src/` が無い)。検査する対象が無いため、テストは置かない。

`node tools/check-package-shape.mjs` も明示的に対象外にしている
(「テストが無いパッケージ」を数えるときは、ここを除いて **112 件**が母数)。
