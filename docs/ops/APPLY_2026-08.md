# 適用手順（2026-08 の変更をどの順で入れるか）

**この資料は使い捨てです。** 適用が済んだら削除してください
（ルート直下と `docs/ops/` に一時的な資料を残さないため）。

一連の作業で入れた変更のうち、**順序を守らないと壊れるもの**があります。
特に **`WageRow.hourlyWage` の `Float → Int`** は、既存データがあると失敗します。

## 2. DB を変える（**ここが危険**）

### 2-1. 何が変わるか

| 変更 | 危険度 | 理由 |
|---|---|---|
| **索引 6 本の追加** | 低 | 追加のみ。既存データに影響しない |
| **`WageRow.hourlyWage` を `Float → Int`** | **高** | **端数のある時給があると、丸めで給与が変わる** |

### 2-2. 時給の移行

**順序を守ってください。**

```bash
# STEP 1: 端数のある時給が無いか確かめる（**0 件でなければ止まる**）
psql "$DATABASE_URL" -c \
  'SELECT count(*) FROM "WageRow" WHERE "hourlyWage" <> round("hourlyWage"::numeric);'
```

**0 件でなければ、そこで止めてください。**
丸めると**その人の給与が変わります**。誰がいくら変わるかを一覧にして、
人事の合意を取ってから進めます。

```sql
-- 誰がどう変わるか
SELECT "userId", "hourlyWage", round("hourlyWage"::numeric) AS after
FROM "WageRow" WHERE "hourlyWage" <> round("hourlyWage"::numeric);
```

0 件だったら:

```bash
# STEP 2: バックアップ（docs/ops/BACKUP_RESTORE.md）
bash scripts/backup.sh

# STEP 3: 変換
psql "$DATABASE_URL" -f scripts/migrate-money-to-int.sql

# STEP 4: スキーマを反映（索引もここで入る）
node tools/apply-schema.mjs internal-app
```

**`db push` に任せないでください。** `double precision → integer` は
`--accept-data-loss` を要求され、**何がどう丸められたか記録が残りません**。

### 2-3. 索引の追加だけ先に入れてもよい

時給の判断に時間がかかるなら、**索引だけ先に入れて構いません**（追加のみで安全）。
その場合は schema の `hourlyWage` を一時的に `Float` に戻してから
`apply-schema.mjs` を叩き、あとで 2-2 をやり直してください。

## 3. サーバの設定を入れる

```bash
# compose を転送してから
cd ~/app
docker compose -f docker-compose.prod.yml up -d
```

**ログの上限**（`max-size: 100m`）が効きます。既に溜まっている分は消えないので、
必要なら手で消してください。

```bash
# いま何 GB 使っているか
docker system df
# 溜まったログを捨てる（コンテナは止まりません）
sudo truncate -s 0 /var/lib/docker/containers/*/*-json.log
```
