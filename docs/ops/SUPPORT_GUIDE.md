# 利用者からの問い合わせに答える

情シスが実際に受ける問い合わせと、その場でできる対応をまとめます。

**大半は「システムの障害ではない」**ものです。まずここを見て、当てはまらなければ
`RUNBOOK.md` の障害対応へ進んでください。

---

## ログインできない

利用者は全部を「ログインできない」と言います。**どこで止まっているか**を先に聞きます。

| 症状 | 原因 | 対応 |
|---|---|---|
| 「メールまたはパスワードが違います」 | 打ち間違い・パスワード忘れ | 再設定リンクを送る（下記） |
| 「試行回数が多すぎます」 | 総当たり対策が働いた | **15 分待つ**。急ぐなら記録を消す（下記） |
| 2 要素のコードが通らない | **端末の時計のずれ** | 端末の日時を自動設定にしてもらう。急ぐなら予備コード |
| 予備コードも無い | 端末の紛失 | 本人確認のうえ、管理者が 2 要素を解除する |
| SSO の画面から戻ってこない | IdP 側の問題 | Entra ID / Google Workspace の管理画面を見る |

### パスワードの再設定

`@platform/auth` の使い捨てリンクを送ります。

- **有効期限は 30 分・1 回だけ**。切れたら送り直す
- **未登録のアドレスでも同じ応答**を返す（登録の有無を外に漏らさないため）
- 再設定が終わったら、**その人の既存セッションを無効化**する
  （新しいパスワードにしても、盗まれたセッションが生きていては意味がない）

### 試行回数の制限を解除する

回数制限は **メール単位（15 分で 5 回）** と **接続元単位（15 分で 20 回）** の 2 つです。
待てば自動で解けます。急ぐ場合だけ、記録を消してください。

> **本人からの依頼かどうかを必ず確かめること。**
> 「ログインできない」と電話をかけて解除させるのは、攻撃の手口として実在します。

## 画面が出ない・エラーが出る

| 画面 | 意味 | 対応 |
|---|---|---|
| 「この画面はありません」 | URL の誤り。**障害ではない** | 正しい URL を案内。ブックマークが古い可能性 |
| 「この画面を表示できませんでした」 | その画面だけの例外 | **識別子（digest）を聞く**。記録と突き合わせる |
| 真っ白 | 受け皿が無い画面か、通信の失敗 | ブラウザの再読み込み。続くなら記録を見る |
| 「接続できません」 | 圏外・Wi-Fi の切断 | 電波を確認。一度開いた画面は見られる場合がある |

**識別子（digest）は必ず聞いてください。** サーバの記録と結び付く唯一の手がかりです。

---

## 「権限がありません」と出る

権限は**業務を知る人が判断**します。情シスが独断で付けないでください（ADR 0017）。

1. その人の所属と役割を確認する
2. **本当にその操作が必要か**を、所属部署の責任者に確認する
3. 付けるときは、`docs/ops/ACCESS_CONTROL.md` の手順で記録を残す

強い権限（`*` / `pii:unmask` / `system:manage`）は**期限を決めて**付けます。
「いつか使うかもしれない」で恒久的に持たせないでください。

## 動きが遅い

| 状況 | 見るところ |
|---|---|
| 特定の画面だけ遅い | 件数が増えていないか（一覧の絞り込みを案内する） |
| 全体が遅い | `/api/health` の応答。DB が落ちかけていないか |
| 特定の人だけ遅い | 端末・回線。他の人で再現するか確かめる |
| 朝だけ遅い | 一斉ログインの集中。時間をずらせないか検討 |

**「遅い」は主観**なので、いつ・どの画面で・どのくらい待ったかを聞きます。

---

## データが見当たらない

消したのか、見えていないだけかを切り分けます。

1. **絞り込みが残っていないか**（検索語・期間・状態）
2. **権限で見えていない**のではないか（他の人には見えるか）
3. **無効化されている**のではないか（マスタは削除せず無効化する作りです）
4. 監査ログに削除の記録があるか（`@platform/audit`）

**「消えた」と言われても、まず消していないことを疑ってください。**
この基盤は削除を避け、無効化と履歴で残す作りにしてあります。

---

## メールが届かない

| 確認 | 内容 |
|---|---|
| 迷惑メール | 最初に確認してもらう。社内システムからの通知は分類されやすい |
| アドレスの誤り | 登録内容を確認する |
| 送信側の失敗 | 記録を見る（`@platform/mail` は失敗を記録します） |
| 相手のサーバ拒否 | ドメインの設定（SPF / DKIM）を確認 |

---

## 答えられないとき

**その場で解決しようとしないでください。** 次を聞いて記録し、折り返します。

- いつ（日時）
- どの画面（URL）
- 何をしたら（操作）
- 何が起きたか（画面の文言・識別子）

この 4 つが揃えば、記録から追える可能性が高くなります。
