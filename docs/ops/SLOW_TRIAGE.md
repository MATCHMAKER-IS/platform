# 「遅い」と言われたときの切り分け

**100 人規模では、「落ちた」より「遅い」の方が多くなります。**

落ちたときは `INCIDENT_RESPONSE.md` を見てください。
ここは**動いているのに遅い**ときの手順です。

---

## まず聞くこと（3 つだけ）

**闇雲に調べる前に、これだけ聞いてください。**
**答えによって、見る場所が変わります。**

| 聞くこと | なぜ |
|---|---|
| **どの画面ですか** | 「全部遅い」なら DB かサーバ、**1 つだけなら索引** |
| **いつからですか** | 「今朝から」なら**直近の変更**。「だんだん」なら**件数の増加** |
| **他の人もですか** | 自分だけなら**端末か回線**。全員なら**サーバ側** |

**「全部遅い」と言われても、まず 1 つ具体的な画面を出してもらってください。**
人は「全部」と言いがちですが、**実際は 1 つの画面のことが多い**です。

---

## 切り分けの順番

**上から順に見てください。** 下ほど調べるのが大変です。

### 1. その人だけか、全員か（1 分）

```bash
# 自分でその画面を開いてみる
```

**自分は速いなら、サーバ側ではありません。**
端末・ブラウザ・回線を疑ってください——
**古い PC で Chrome のタブを 50 個開いている**、はよくあります。

### 2. サーバの応答か、画面の描画か（3 分）

**ブラウザの開発者ツール → ネットワーク**を見てもらってください。

| 見るもの | 遅い場合 |
|---|---|
| **リクエストの時間** | **サーバ側**（次へ進む） |
| リクエストは速いのに画面が遅い | **画面側**（描画・JavaScript） |

**画面側なら**、`summarizeVitals`（`@platform/analytics`）で
**どの画面の何が遅いか**を見てください。

### 3. どのクエリが遅いか（5 分）

**サーバ側なら、まず遅いクエリを見ます。**

```ts
// createDb の onQuery に slowQueryLog.record を繋いでおくと、
// ここで「何が遅いか」が分かります
slowQueryLog.summary();
```

**回数の多いものから直してください。**
1 回だけ遅いものより、**毎回遅いものの方が効きます**。

### 4. 索引が効いているか（10 分）

```sql
EXPLAIN ANALYZE SELECT ... ;
```

**`Seq Scan`（全件走査）が出たら索引が足りません。**
詳しくは `LOAD_TESTING.md` の「遅かったときに見るところ」へ。

### 5. 件数が増えていないか（10 分）

```sql
SELECT relname, n_live_tup FROM pg_stat_user_tables ORDER BY n_live_tup DESC LIMIT 10;
```

**急に増えた表**があれば、そこが原因です。
**保持期間の削除が走っていない**（`HANDOVER.md` の 2 番目）かもしれません。

---

## よくある原因と、その見分け方

| 症状 | 疑うもの | 見分け方 |
|---|---|---|
| **一覧だけ遅い** | 索引 / `take` が無い | 件数を確認。**数千件なら索引** |
| **だんだん遅くなった** | 件数の増加 | `n_live_tup` を見る |
| **朝だけ遅い** | 定期実行と重なっている | `notify-scheduler` の時刻を確認 |
| **特定の人だけ遅い** | その人のデータが多い | **権限で絞られていない**かも |
| **たまに遅い** | ロック待ち | `pg_locks` を見る |
| **全部が急に遅い** | 直近のデプロイ | **戻すのが最優先** |

---

## やってはいけないこと

| やりがちなこと | なぜ避けるか |
|---|---|
| **いきなりサーバを増やす** | **メモリ実装のままだと壊れます**（`HANDOVER.md` の 1 番目） |
| **キャッシュで隠す** | 原因が残り、**古いデータが出る**問題が増えます |
| **本番で `EXPLAIN` 以外を試す** | **業務中に重いクエリを流すと、さらに遅くなります** |
| **原因が分かる前に直す** | **直したつもりで直っていない**ことに気づけません |

---

## 直したら記録してください

**「何が原因で、何をしたら速くなったか」**を
`HANDOVER.md` の「気づいたこと」に書いてください。

**同じ調査を次の人が繰り返さないため**です。
**数字だけ残しても、次の人には何も伝わりません。**
