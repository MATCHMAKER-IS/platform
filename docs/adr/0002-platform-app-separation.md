# ADR 0002: 基盤(packages)とアプリ(apps)の分離

- 状態: 承認
- 日付: 2026-07-09

## 背景
共通機能をアプリ内に散在させると重複・表記ゆれ・属人化が進む。一方、基盤を
アプリから自由に編集できると「共通部品」の意味が崩れる。

## 決定
- 共通機能は `packages/@platform/*` にラッパーとして集約し、公開 API のみ露出する。
- アプリは基盤の公開 API を使うだけで、`packages/` のソースは編集しない。
- 境界は ESLint(boundaries)・CODEOWNERS・CI・CLAUDE.md で多層に強制する。

## 結果
- ライブラリ差し替えが基盤内部で完結し、アプリは無変更。
- 基盤変更にレビュー負荷がかかる(意図的な摩擦。品質の担保として許容する)。

## 現況（2026-08 追記）

**分離をさらに進めました。** `apps/` は**基盤の git では管理しません**（`.gitignore`）
——アプリごとに、その中で別の git を切ります。

**なぜここまでするか**:

- **基盤はアプリを保証できない**。アプリを直すたびに基盤側の資料や検査を直すのは、責任の境界が曖昧
- **試し書きやゴミを置ける**。消し忘れても基盤の履歴が汚れない
- アプリごとに**別のチームが別の速さで**改修できる

**例外は 2 つ**——`crud-template`（`pnpm new-app` のコピー元）と
`showcase`（16 のツールが前提にする見本）は基盤の git に入れています。
`templates/` へ移す案は却下しました——**workspace から外れると
`@platform/*` の依存が解決されず、雛形が壊れていても気づけません**。

**アプリの資料もアプリの中**に置きます（`apps/<名前>/docs/appmap.md` など）。

**この決定は変えません。** 変えるとしたら、
「**アプリのリポジトリだけで CI が回らない**」（`workspace:*` 依存のため
基盤を clone する必要がある）が耐えられなくなったときです。
その場合は npm への公開（ADR 0011 の再検討）が必要になります。
