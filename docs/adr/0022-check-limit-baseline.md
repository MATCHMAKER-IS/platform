# 0022: 検査は「上限方式」で増やさせない

- 日付: 2026-08-13 / 状態: 採用

## 文脈（なぜ決める必要があったか）

**既にあるものを全部直してから検査を入れる**のは、現実的ではありません。

例: **確認なしの削除が 9 件**あるとき、
「9 件すべてに確認を足してから検査を入れる」では、**検査がいつまでも入りません**。

一方、**検査を入れずに放置**すると、**10 件、20 件と増えます**——
**誰も「増えた」ことに気づけません**。

## 決定

**いまの数を上限として記録し、それを超えたら落とす**方式にする。

```bash
node tools/check-なんとか.mjs --list       # 対象の一覧
node tools/check-なんとか.mjs --set-limit  # いまの数を上限に
```

上限は `tools/<名前>-limit.json` に保存する（**2026-08 時点で 18 本**）。

### 守ること

| | |
|---|---|
| **`--list` を必ず付ける** | **どれが対象か分からないと、減らせません**——**上限を守るだけ**になります |
| **減らしたら上限も下げる** | **下げないと、また増やせます**（smoke が「上限と現在値の一致」を見張っています） |
| **上限を上げるときは理由を書く** | HANDOVER に**なぜ増やしてよいか**を残してください |

## 理由

**「全部直してから」を待つと、検査が入りません。**
**入れないと増え続けます**——**入れてから減らす**方が確実です。

**上限 0 にできるものは 0 にしてください。**
2026-08 時点で、**18 本中 12 本が上限 0**（`api-auth` など）——
**新しい違反を 1 件も許さない**ものです。

## 弱点（必ず知っておくこと）

**上限を現状に合わせると、減らす動機が無くなります。**

`check-delete-confirm` は **9 件 / 上限 9** で、
「これ以上増えない」は守れていましたが、**9 件が放置**されていました。

**定期的に `--list` を見て、危ないものから減らしてください。**
2026-08 に **9 → 6 件**に減らしました（予約の取り消し・CMS ページの削除・経費の一括取り消し）。

**ただし、一覧に出たものが全部危ないわけではありません**——
チャットの「ピン留めを外す」は**また留められる**ので確認は要りません。
**中身を読んでから**判断してください。

## 覆すとしたら

**上限が長く動いていない検査**は、**上限 0 にできないか**を考えてください。
「減らせないから上限方式」だったものが、**いつの間にか減っている**ことがあります。

**逆に、上限が増え続ける検査**は、**そもそもその約束が現実的でない**のかもしれません。
**検査を消すか、約束を変える**ことを検討してください。
