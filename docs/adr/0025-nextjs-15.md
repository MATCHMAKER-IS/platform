# 0025: Next.js は 15 系に固定する（Amplify の対応範囲に合わせる）

- 日付: 2026-08-18 / 状態: 採用（2026-08-18 に「EOL 後も 15 のまま待つ」と追記）

## 文脈(なぜ決める必要があったか)

基盤は Next.js **16.2.0** で作られていました。手元では問題なく動きます
——`pnpm dev` も `next build` も通ります。

しかし置き先は **AWS Amplify Hosting** です。AWS の公式ドキュメントによれば、
Amplify Hosting compute が完全に対応するのは **Next.js 12〜15** で、
現行の SSR プロバイダが対応するのは **Next.js 15** です（2026-08 時点）。
**16 は対応外**です。

問題はこの食い違いの見つかり方です。

> **手元では 16 でも動きます。気づくのは Amplify に上げたときです。**

そのときには「なぜか本番だけ動かない」を追うことになります。
`pnpm up --latest` のような何気ない操作でも上がってしまいます。

## 決定

**Next.js は 15 系（`^15.5.21`）に固定します。**

- 下限を `15.5.21` にしたのは、2026-08 の security release で
  4 件の HIGH と 5 件の MEDIUM が塞がれた版だからです。
  **上限は付けません**（`^` で 15.5.x の修正を取り続けます）。
- 入口のファイル名は **`middleware.ts`** です（Next 16 の `proxy.ts` ではない）。
- `next build` は **webpack** になります（16 は Turbopack が既定）。
  そのため各 `next.config.mjs` に **`outputFileTracingRoot`** を明示しました
  ——monorepo では基点を推測するので、指定しないと
  **必要なファイルが成果物から漏れます**。
- `tools/check-next-version.mjs` で**版が範囲外になったら落とします**。
  人の注意には頼りません。

## 検討した代替案と見送り理由

**(A) Next 16 のまま置く。**
動く可能性はありますが、**動かなかったときに AWS へ相談できません**。
社内基盤で「公式に対応外の構成」を選ぶのは、
属人化を避けるという目的と噛み合いません。見送りました。

**(B) Amplify をやめて別の置き先にする（Vercel / ECS / Lambda Web Adapter）。**
Next 16 をそのまま使えます。ただし**この判断は基盤の話を超えます**
——課金・権限・監視・社内の運用手順が全部変わります。
必要になったら別の ADR で扱います。

**(C) 15 系のうち古い版に留める。**
security release を取り逃がします。選ぶ理由がありません。

## 影響(良い点・受け入れるコスト・関連ドキュメント)

**良い点**
- 置き先が公式に対応する構成になり、**問題が起きたとき AWS に聞けます**。
- 検査で固定したので、**うっかり 16 に戻ることがありません**。

**受け入れるコスト**
- **Next 15 は Maintenance LTS で、2026-10-21 に公式サポートが終わります。**

  **2026-08-18 の判断: 期限が切れても Next 15 のまま進めます。**
  Amplify が 16 に対応するまで、こちらから動かないという意味です。

  **これは「決めていない」のではなく、「待つと決めた」ものです。**
  置き先を変える（代替案 B）方が技術的には自由になりますが、
  課金・権限・監視・社内の運用手順が全部変わるので、
  **framework の版のためだけに動かす理由にはなりません。**

  ただし**受け入れているリスクは書いておきます**——
  サポート終了後は、**Next 15 に脆弱性が出ても修正版が出ません**。
  出た場合の選択肢は 3 つです:
  1. Amplify の 16 対応を待つ（それまで露出したまま）
  2. 置き先を変える（代替案 B。**急ぐと事故ります**）
  3. 有償の延長サポート（HeroDevs 等）を買う

  **1 を選ぶなら、脆弱性の内容次第では「待てない」こともあります。**
  10 月が近づいたら、Amplify の対応状況を確認してください
  （`tools/check-next-version.mjs` の `MAX_MAJOR` を上げるのはその後）。
- `next build` が webpack になるぶん、ビルドは 16 より遅くなります。
- 開発時に Turbopack を使いたい場合は `next dev --turbopack` を付けてください
  （15 では既定ではありません）。**ビルドは webpack なので、
  開発とビルドで束ね方が変わる**点は承知の上で選んでください。

**確かめること（未検証）**
- `apps/internal-app/src/middleware.ts` の **`export const runtime = "nodejs"`**
  が Amplify Hosting compute で動くか。Next 15.5 で正式版になった指定ですが、
  **Amplify 側の対応は公式ドキュメントに記載が見つかりませんでした**。
  動かない場合は、環境変数を静的参照に直すか、
  メンテナンスゲートを画面側（layout）へ移してください。
- `output: "standalone"`（`internal-app`）と Amplify の組み合わせ。
