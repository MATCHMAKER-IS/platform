# ここに自分のアプリを作ります

**このフォルダの中身は、基盤の git で管理していません**（`.gitignore` を見てください）。
**アプリごとに、その中で別の git を切ってください。**

## 【最優先】基盤のソースは編集しない

**アプリを作っている最中に `packages/` と `tools/` を変更しないでください。**

**基盤は他のアプリも使っています。** アプリの都合で直すと、
**気づかないうちに他のアプリを壊します**——しかも壊れたことは
**そのアプリを次に触った人**が知ることになります。

**不具合や要望は、基盤リポジトリへ Issue を立ててください。**
テンプレートは `.github/ISSUE_TEMPLATE/platform-request.md` にあります。

**急ぎで待てないときは、自分のアプリの中に回避を書いて**ください
（基盤を直すより安全です）。**必ず印を付けてください**:

```ts
// **基盤の <関数名> が <できないこと> なので、ここで回避しています。**
// Issue: <URL>
// 基盤が直ったら、この関数を消して基盤のものに戻してください。
```

**この印が無いと、次の人は「なぜ自前実装なのか」が分かりません。**

## なぜ分けるか

| 理由 | |
|---|---|
| **基盤はアプリを保証できない** | アプリを直すたびに基盤側の資料や検査を直すのは、責任の境界が曖昧です |
| **試し書きを置ける** | 消し忘れても基盤の履歴が汚れません |
| **別の速さで改修できる** | アプリごとに別のチームが動けます |

## 作り方

```bash
pnpm new-app my-app "経費の申請と承認"
cd apps/my-app
git init            # ここで別の git を切る
```

`crud-template` がコピーされ、**画面 1 つ + API 4 つ**が動く状態から始まります。

### 使う機能を選べます

作るときに聞かれます（**26 個・8 分類**。後から足せます）。

| 分類 | 選べるもの |
|---|---|
| **ログイン・権限** | 自前ログイン / SSO（Google・Microsoft）/ API キー |
| **通知** | メール / Slack・LINE |
| **ファイル・帳票** | アップロード / PDF / CSV・Excel の取り込み |
| **業務ドメイン** | 請求書・見積 / 会計 / 勤怠・給与 / 在庫・発注 / 契約 |
| **コミュニケーション** | チャット / 掲示板・FAQ / CMS |
| **検索・AI** | 全文検索 / AI / 社内文書の検索（RAG） |
| **外部サービス連携** | Zoho / LINE / freee |
| **仕組み** | 承認フロー / 定期実行 / 段階公開 / 多言語 |

選ぶと、**依存・環境変数・雛形のコード・README の説明**がまとめて入ります。

**UI・テーマ・DB・認可・監査ログは最初から入っています**——
**選ぶまでもなく全アプリで要る**ものだからです
（`@platform/ui` `theme` `db` `auth` `audit` など 17 個）。

**手順書や CI では引数でも指定できます**（対話は端末でしか動かないため）:

```bash
pnpm new-app my-app "説明" --features=login,invoice,workflow
pnpm new-app my-app "説明" --yes            # 何も足さない（最小構成）
```

**選ばなかった機能は何も入りません。** 後から足したくなったら
`tools/app-features.mjs` の定義を見てください——**繋ぎ方の見本**になっています。

## 基盤の資産（消さないでください）

**この 2 つだけは基盤の git で管理しています。**

| | 役割 |
|---|---|
| **`crud-template/`** | `pnpm new-app` のコピー元。**無いと新しいアプリを作れません** |
| **`showcase/`** | 基盤の見本。**16 のツールが前提**にしています（ポータル・参照サイト・索引） |

## 検査はアプリにも効きます

**`pnpm check` は `apps/` の中も見ます**（72 種類のうち 50 が対象）。

- API に認可が付いているか
- 金額・日付・率の表示が揃っているか
- 一覧に並び順の指定があるか
- 削除に確認があるか

**git で管理していなくても、手元で走らせれば検査されます。**

**別リポジトリにしたら、CI の雛形が入っています**——
`pnpm new-app` でコピーされる `.github/workflows/ci.yml` です。
**基盤を clone してから、その中にアプリを置いて検査を回す**形になっています
（`<あなたの組織>` の部分を書き換えてください）。

**週 1 回も回すようにしてあります。** 基盤を直した人はアプリを知らないので、
**壊れたことに気づけるのはアプリ側**だからです。
アプリを別リポジトリにしたら、**そちらの CI でも `pnpm check` を回してください**
（基盤を clone する必要があります——`@platform/*` を `workspace:*` で参照しているため）。

## アプリの資料はアプリの中に

```
apps/my-app/
  docs/
    appmap.md   ← 画面と API の一覧（pnpm gen:all で作られます）
    erd.md      ← DB のテーブル図（同上）
  README.md     ← 何をするアプリか
```

**基盤側の `docs/` には置かないでください。** 基盤はアプリを保証しません。
