# balance-app — 口座残高

freee から口座の残高と明細を取り、**推移をグラフで見る**アプリです。

```bash
pnpm --filter balance-app dev    # http://localhost:3006
```

## 鍵が無くても動きます

`FREEE_CLIENT_ID` などが未設定なら、**見本データで動きます**。
画面に「見本のデータです」と明示するので、実データと取り違えません。

鍵が無いと真っ白になる作りだと、「壊れているのか設定が足りないのか」が分かりません。

## 設定

| 環境変数 | 内容 |
|---|---|
| `FREEE_CLIENT_ID` / `FREEE_CLIENT_SECRET` | freee アプリの情報 |
| `FREEE_REFRESH_TOKEN` | **更新のたびに回る**。保存し直さないと失効する |
| `FREEE_COMPANY_ID` | 事業所 ID |

## 押さえていること

| 点 | 内容 |
|---|---|
| **クレジットカードは合算から除く** | 負債なので、足すと実際より多く見える |
| **入出金は符号で判断しない** | freee は金額を正で返す。`entry_side` で見る |
| **最小とその日を目立たせる** | 資金繰りで最初に見るのは「いくらあるか」ではなく「いつ足りなくなるか」 |
| 残高は同期に依存する | 銀行と繋いでいない口座は**帳簿上の残高**。実際と一致しないことがある |

## 計算はどこにあるか

残高の推移は `@platform/freee` の `buildBalanceHistory` が行います
（**今の残高から過去へ遡る**。明細の `balance` は欠けることがあるため）。

このアプリが持つのは、取得・整形・画面だけです。

## 定期取得（1 日に数回）

残高を取って記録し、**古いものを間引きます**。

```bash
curl -X POST http://localhost:3006/api/collect \
  -H "Authorization: Bearer $COLLECT_SECRET"
```

cron の例（9 時・13 時・18 時）:

```
0 9,13,18 * * * curl -sS -X POST https://balance.example.co.jp/api/collect -H "Authorization: Bearer ***"
```

### 何を残すか

| 対象 | 扱い |
|---|---|
| **今月ぶん** | すべて残す（日々の動きを見たい） |
| **先月以前** | **月末の 1 件だけ**残す（推移が分かればよい） |
| 同じ日に複数回 | その日の最後の 1 件を残す |

1 日 3 回・4 口座で 1 年ためると 4,380 件になりますが、
間引き後は **今月ぶん + 過去 11 か月 × 4 口座 = 約 400 件**に収まります。

### 消す前に確かめます

**「残すもの」を先に決めてから消します。** 消すものを選ぶ形だと、
条件の書き間違いで全部消えます。

さらに `verifyRetention` が「月末の記録が消えていないか」を確認し、
**おかしければ削除を見送って 207 を返します**（監視で気づけるように）。

### 鍵について

`COLLECT_SECRET` が未設定なら **503 を返して実行しません**。
開けっ放しにすると、誰でも freee への通信を起こせてしまいます。
